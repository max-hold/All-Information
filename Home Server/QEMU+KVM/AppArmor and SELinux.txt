# Extra layer of security on your host machine 
- So that even if QEMU has a serious bug or someone escapes the VM, the damage to your real computer is limited.

### Mandatory Access Control (MAC) systems.
- Normal Linux permissions (chmod, chown) are Discretionary — a program can do whatever the user who started it is allowed to do.
- MAC systems say: “Even if you are root or the user, you are only allowed to do these exact things defined in a policy.”

- AppArmor = Ubuntu’s default security module (very lightweight, path-based).
- SELinux = Red Hat/Fedora’s security module (very powerful, label-based, more complex).


1. AppArmor line:
```
sudo aa-enforce /etc/apparmor.d/usr.bin.qemu-system-x86_64
# “create a profile” if the file doesn’t exist
```

- `aa-enforce` = tells AppArmor to load the profile and actually block anything the profile doesn’t allow (instead of just logging it).
The profile file (/etc/apparmor.d/usr.bin.qemu-system-x86_64) contains a list of permissions QEMU is allowed to have: 
    - Read/write specific disk images
    - Access /dev/kvm
    - Use the network (but only what you allow)
    - Open the GTK window

# Check if AppArmor profile for QEMU already exists
```
ls /etc/apparmor.d/*qemu*
```

# If you see a profile, just enforce it:
```
sudo aa-enforce /etc/apparmor.d/usr.bin.qemu-system-x86_64
```

# Check status
```
sudo aa-status | grep qemu
sudo aa-logprof 
journalctl -xe
```


2. SELinux lines:
```
sudo semanage fcontext -a -t qemu_exec_t "/usr/bin/qemu-system-x86_64"
restorecon -v /usr/bin/qemu-system-x86_64
```

- `semanage fcontext` = adds a permanent rule that says “this binary should have the SELinux type qemu_exec_t”.
- `restorecon` = actually applies that label to the file right now.

- This is the SELinux way of saying “treat this QEMU binary with the special security context that the QEMU policy expects.”
- SELinux is not worth it — Ubuntu does not enable SELinux by default. Installing and configuring it properly is a lot of work and usually breaks things for desktop users. You can safely ignore the entire SELinux bullet.

Why it’s in the guide:
The author was trying to make a “production-grade secure kiosk”. In enterprise or public-facing environments this kind of hardening is standard and smart.
For your specific situation (personal disposable Alpine browser VM on Ubuntu):

AppArmor is worth enabling — it’s lightweight and Ubuntu already has it running. It adds real protection for almost zero cost.
SELinux is not worth it — Ubuntu does not enable SELinux by default. Installing and configuring it properly is a lot of work and usually breaks things for desktop users. You can safely ignore the entire SELinux bullet.

Simple recommendation for you right now
If you want to apply the useful part:
# Check if AppArmor profile for QEMU already exists
ls /etc/apparmor.d/*qemu*

# If you see a profile, just enforce it:
sudo aa-enforce /etc/apparmor.d/usr.bin.qemu-system-x86_64

# Check status
sudo aa-status | grep qemu
That’s it.
You do not need to create a custom profile unless you start hitting denials (you can check logs with sudo aa-logprof or journalctl -xe).
