🔴 1. Critical Errors
❌ 1. Static VM IP assumption (192.168.100.2)

You repeatedly hardcode:

VM_IP="192.168.100.2"

Problem:

    There is NO DHCP server configured anywhere

    TAP + NAT ≠ DHCP

    Cloud-init is set to dhcp4: true, but nothing is serving DHCP

👉 Result:
The VM will not get an IP, and all of this will fail:

    SSH wait loop

    VNC wait loop

    File monitor

✅ Fix (choose one):
Option A (recommended for simplicity): Static IP in cloud-init

Replace network-config with:

version: 2
ethernets:
  eth0:
    match:
      name: "en*"
    addresses:
      - 192.168.100.2/24
    gateway4: 192.168.100.1
    nameservers:
      addresses: [8.8.8.8, 1.1.1.1]

Option B (proper way): Add dnsmasq DHCP server (better design)

Install:

sudo apt install dnsmasq

Configure for TAP interface.
❌ 2. Missing virtio-blk root device alignment risk

You use:

--disk path=ubuntu-browser.img
--cmdline "root=/dev/vda1"

Problem:

    This assumes disk is always exposed as /dev/vda

    Cloud Hypervisor usually uses virtio-blk → vda ✔

    But not guaranteed if config changes

✅ Safer fix:

Use UUID instead:

blkid ubuntu-browser.img

Then:

root=UUID=xxxx-xxxx

❌ 3. Cloud-init SSH key injection is WRONG placement

You appended:

ssh_authorized_keys:
  - ${SSH_PUBKEY}

Problem:

    This is at top-level, not inside user definition

    It may not apply to browser user

✅ Correct:

users:
  - name: browser
    ...
    ssh_authorized_keys:
      - ${SSH_PUBKEY}

❌ 4. VNC server startup is unreliable

su -c 'vncserver :1 ...' browser

Problems:

    Runs once during cloud-init

    No restart on reboot

    No systemd service

    XFCE session may fail without proper DISPLAY

✅ Fix (production-grade):

Create systemd service:

/etc/systemd/system/vncserver@.service

Example:

[Unit]
Description=VNC Server

[Service]
Type=forking
User=browser
ExecStart=/usr/bin/vncserver :1 -geometry 1920x1080 -depth 24
ExecStop=/usr/bin/vncserver -kill :1
Restart=always

[Install]
WantedBy=multi-user.target

Then:

systemctl enable vncserver@1
