You’re actually hitting one root error, and everything else is just a cascade from it.

🔴 The real problem
Failed to create 'C:\VMs\IsolatedBrowser.vhdx': The file exists. (0x80070050)

This means:
👉 The virtual disk file already exists at:

C:\VMs\IsolatedBrowser.vhdx

So New-VM fails immediately.

⚠️ Why all the other errors happen

Because this line failed:

$buildVM = New-VM ...

👉 $buildVM becomes null

So every later command using $buildVM.Name fails with:

The argument is null or empty
✅ How to fix it
Option 1: Delete the existing VHD (simplest)

If you don’t need the old disk:

Remove-Item "C:\VMs\IsolatedBrowser.vhdx"

Then rerun your script.

Option 2: Use a different VHD name

Change this line:

-NewVHDPath "C:\VMs\IsolatedBrowser.vhdx"

to something like:

-NewVHDPath "C:\VMs\IsolatedBrowser2.vhdx"
Option 3: Reuse existing disk (advanced)

If the disk is valid and you want to reuse it:

New-VM -Name "IsolatedBrowser-Build" `
    -MemoryStartupBytes 2GB `
    -Generation 2 `
    -VHDPath "C:\VMs\IsolatedBrowser.vhdx"
⚠️ Another issue in your command

You wrote:

Set-VMDvdDrive -VMName $buildVM.Name -Path "C:\Users\Hima Window\OneDrive\Desktop"

That is wrong ❌

👉 It must point to an ISO file, not a folder.

Correct example:

Set-VMDvdDrive -VMName $buildVM.Name -Path "C:\ISOs\alpine-extended-3.20-x86_64.iso"
✅ Clean working version
$buildVM = New-VM -Name "IsolatedBrowser-Build" `
    -MemoryStartupBytes 2GB `
    -Generation 2 `
    -NewVHDPath "C:\VMs\IsolatedBrowser2.vhdx" `
    -NewVHDSizeBytes 10GB

Set-VMProcessor $buildVM.Name -Count 2

Set-VMDvdDrive -VMName $buildVM.Name `
    -Path "C:\ISOs\alpine-extended-3.20-x86_64.iso"

Set-VMFirmware -VMName $buildVM.Name -EnableSecureBoot Off

Start-VM $buildVM.Name

You’ve now got two separate issues, and they’re both very fixable.

🔴 Issue 1: Secure Boot error
Cannot modify the secure boot property while the virtual machine is running
✅ What happened

You tried:

Set-VMFirmware ...

after the VM already started

👉 Hyper-V does NOT allow firmware changes while the VM is running.

✅ Fix

Stop the VM first:

Stop-VM "IsolatedBrowser-Build" -Force

Then run:

Set-VMFirmware -VMName "IsolatedBrowser-Build" -EnableSecureBoot Off
🔴 Issue 2: Not enough memory
Not enough memory resources... 2048 MB
✅ Why this happens

Your system doesn’t have enough free RAM for a 2GB VM

Common reasons:

Too many apps open (browser, IDEs, etc.)
Other VMs already running
Hyper-V reserved memory
✅ Fix options (pick one)
Option A: Lower VM RAM (fastest fix)

Alpine Linux is lightweight — you don’t need 2GB.

Use 512MB or 1GB:

Set-VM -Name "IsolatedBrowser-Build" -MemoryStartupBytes 1GB

or even:

Set-VM -Name "IsolatedBrowser-Build" -MemoryStartupBytes 512MB
Option B: Enable Dynamic Memory (best)

This lets Hyper-V adjust RAM automatically:

Set-VM -Name "IsolatedBrowser-Build" -DynamicMemory
Set-VM -Name "IsolatedBrowser-Build" -MemoryMinimumBytes 512MB
Set-VM -Name "IsolatedBrowser-Build" -MemoryMaximumBytes 2GB
Option C: Free system RAM
Close Chrome/Edge tabs
Stop other VMs:
Get-VM | Stop-VM -Force
✅ Recommended clean sequence

Run this in order:

Stop-VM "IsolatedBrowser-Build" -Force -ErrorAction SilentlyContinue

Set-VMFirmware -VMName "IsolatedBrowser-Build" -EnableSecureBoot Off

Set-VM -Name "IsolatedBrowser-Build" -MemoryStartupBytes 1GB

Start-VM "IsolatedBrowser-Build"
⚠️ One important note

For Alpine Linux, disabling Secure Boot is correct 👍
But you only need to do it once before first boot.

🧠 Pro tip (to avoid this forever)

Always configure VM before starting it:

New-VM ...
Set-VMProcessor ...
Set-VMDvdDrive ...
Set-VMFirmware ...

🔴 What the error means

From your screenshot:

A boot image was not found
The boot loader did not load an operating system

👉 Translation:

No OS is installed on the virtual disk yet ✅ (expected)
AND your ISO (installer) is not attached or not booting ❌
🧠 Root cause (based on your earlier command)

You previously used:

Set-VMDvdDrive -Path "C:\Users\Hima Window\OneDrive\Desktop"

👉 That’s a folder, not an ISO file — so Hyper-V has nothing bootable.

✅ Fix it in 3 steps
1. Attach the correct ISO

Make sure you have the Alpine ISO, e.g.:

C:\ISOs\alpine-extended-3.20-x86_64.iso

Then run:

Set-VMDvdDrive -VMName "IsolatedBrowser-Build" `
  -Path "C:\ISOs\alpine-extended-3.20-x86_64.iso"
2. Set boot order (VERY important)

Hyper-V is trying:

Network boot ❌
Disk (empty) ❌

👉 You need DVD first:

Set-VMFirmware -VMName "IsolatedBrowser-Build" -FirstBootDevice (Get-VMDvdDrive -VMName "IsolatedBrowser-Build")
3. Restart VM
Restart-VM "IsolatedBrowser-Build"
✅ What you should see next

Instead of that error, you should get:

Alpine Linux boot menu
Or a black screen with boot options
⚠️ If it STILL doesn’t work

Check these:

✔ ISO path is correct
Test-Path "C:\ISOs\alpine-extended-3.20-x86_64.iso"

→ Must return True

✔ Secure Boot is OFF (you already did this, good)
Set-VMFirmware -VMName "IsolatedBrowser-Build" -EnableSecureBoot Off
✔ ISO actually exists (not empty or corrupted)
🔥 Quick GUI fix (easiest)

If PowerShell is annoying, do this:

Open Hyper-V Manager
